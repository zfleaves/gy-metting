1 方案概述

1.1 建设目标

搭建部门级轻量化 AI 会议纪要中台，解决评审会议纪要编写耗时、决策遗漏、待办责任人不清晰、口头讨论与原始需求脱节等痛点。

🎯 核心目标
  • 不依赖腾讯会议、钉钉会议企业版，支持录音音频上传完成会议纪要生成
  • 集成语雀，输入文档链接自动拉取 PRD 作为需求基线，实现评审变更对照
  • 支持上传本地参考文档（docx/pdf/txt/md），与语雀文档共同构成需求基线
  • 支持业务背景录入、自定义系统提示词，灵活适配不同大模型
  • 输出可读 Markdown + 机器可解析结构化 JSON
  • 支持钉钉机器人消息推送
  • 全量数据本地归档，可回溯审计
  • 中台化设计，支持后续对接其他业务系统

1.2 适用业务场景

  • 产品需求评审会（核心场景，PRD 对照）
  • 技术方案评审会
  • 项目迭代周会、同步例会
  • 各类需要对照参考文档开展的内部评审会议

1.3 建设原则

原则说明
数据内网闭环录音、原始转写文本不出内网；语雀拉取、钉钉推送仅传输非敏感业务数据
模型无关统一 LLM 适配器接口，对接 DeepSeek、通义千问、GLM 等公有或私有化大模型
最小可用优先先实现核心闭环（API + CLI），再叠加增强能力（Web 界面）
可回溯可审计每一次 AI 生成，保存当时的背景、提示词、参考文档快照
向后兼容扩展架构预留接口，未来可对接会议开放平台、OA、项目管理工具

1.4 数据安全分级

安全等级数据类型处理方式
L1 敏感音频文件、原始 ASR 转写文本严格不出内网；仅存储于本地
L2 业务会议纪要结果、结构化 JSON可发送至钉钉等外部渠道，仅传输摘要级内容
L3 公开语雀文档内容可正常拉取，快照本地存储

3 核心功能详细设计

3.1 会议原始材料接入能力

支持三类输入源，可组合使用：

  • 音频文件上传：mp3/wav/m4a，本地离线 ASR 转写
  • ASR 引擎双模可选：主选 Faster-Whisper（本地离线），备选 Qwen3-ASR-Flash（云端 API）
  • 文本资料上传：SRT 字幕文件直接解析，跳过 ASR 环节
  • 参考文档上传：docx/pdf/txt/md，作为评审需求基线

ASR 引擎方案对比

对比维度Faster-Whisper（主选）Qwen3-ASR-Flash（备选）
部署方式本地离线部署云端 API 调用
硬件要求CPU 可运行（INT8），有 GPU 更佳无需本地 GPU
数据安全✅ 音频不出内网⚠️ 音频需上传云端
成本免费开源按 API 调用量计费
中文准确率良好优秀
适用场景普通会议、敏感会议（内网闭环）对准确率要求高的会议
⚠️ 选择建议
  • 默认使用 Faster-Whisper，满足数据内网闭环要求，零成本
  • 当 Faster-Whisper 识别准确率不足时，可切换至 Qwen3-ASR-Flash
  • 敏感会议强制使用 Faster-Whisper，确保音频不出内网

3.2 参考文档接入与快照管理

3.2.1 语雀 PRD 文档拉取

  • 用户输入语雀文档链接，后台使用只读 Token 调用语雀 OpenAPI
  • HTML 转 Markdown（html2text / markdownify），保留表格、代码块
  • 图片下载转存至本地，确保历史回看不失效
  • 快照存入数据库 + 本地文件系统，语雀文档修改不影响历史回看
  • Token 失效、无权限等异常返回明确错误提示
🔒 安全约束 语雀 Token 保存在中台后端配置（建议加密存储，使用环境变量或加密配置文件），前端不传输 Token。推荐使用语雀应用级 Token（限定只读权限和特定知识库），定期轮换并监控失效情况。

3.2.2 本地参考文档上传

  • 支持 docx / pdf / txt / md 格式
  • 后端自动解析提取文本，生成统一参考文档快照
  • PDF 限制：仅支持文本型 PDF（PyMuPDF 提取），扫描件提示用户改用原始文档
  • 超长文档做截断提示，建议只使用相关章节
  • 与语雀文档可组合使用，均作为参考基线

3.3 AI 纪要生成引擎

三层 AI 控制逻辑：

  1. 内置系统模板库：需求评审、技术评审、周会例会模板
  2. 业务背景输入：项目版本、参会人员、历史遗留问题等
  3. 自定义提示词：高级用户完全覆盖系统模板，适配不同大模型

LLM 适配器（模型无关架构）

  • LLMAdapter 抽象层：定义 chat(messages, temperature, max_tokens) 统一接口
  • OpenAI 兼容模式（优先实现）：通过配置 base_url 和 api_key 即可切换模型
  • 原生 SDK 扩展（后续）：DashScope、Zhipu 等

输入组装规则

【业务背景】
{用户填写背景}

【原始需求参考文档】
{语雀快照 / 上传文档快照 / 手动粘贴参考文本}

【会议转写文本】
{ASR/SRT 解析得到的会议对话}

输出策略（二阶段）

📤 二阶段输出策略

一阶段：模型输出 Markdown 格式纪要（适合阅读）

二阶段：基于 Markdown 结果，调用结构化输出生成 JSON（确保格式合法）

若模型不支持结构化输出，则采用正则提取 + json5 宽松解析 + LLM 自修复三级降级

🚫 内置防幻觉约束 所有决策、变更、待办必须来源于会议转写文本；参考文档仅作为基线，未在会议讨论的条目，禁止输出评审结论。

3.4 多渠道消息通知适配

当前实现钉钉机器人推送，输入 Webhook 地址与安全密钥（选填）。支持 Markdown 语法适配。

⚠️ 限制
  • 原型阶段仅实现消息推送，暂不实现自动创建钉钉待办任务
  • 钉钉推送需要部署机器有公网访问能力，纯内网环境无法使用
  • 推送内容仅包含纪要摘要，不包含原始音频和完整转写文本

3.5 数据归档与历史资产管理

数据库保存完整会议记录：会议主题/类型/背景、当时生效的提示词、语雀 PRD 快照/上传文档快照、原始转写文本、Markdown 纪要、结构化 JSON、推送信息、创建时间。

3.6 异步任务队列

特性设计
任务提交立即返回 task_id，任务进入后台队列
任务状态pending → processing → completed / failed，持久化到数据库
结果获取客户端轮询 GET /api/v1/tasks/{task_id}，后续可扩展 WebSocket
队列实现原型阶段使用内存队列 + 数据库状态表
并发控制单机模式下限制同时处理 1 个任务
超时处理单个任务超过 30 分钟标记为超时失败
⏱️ 短会议阈值 音频时长 ≤ 30 分钟可同步处理（仍建议走异步）；超过 30 分钟必须异步。

3.7 标准化对外 API 能力

对外提供 HTTP 接口，入参包括：会议主题、会议类型、业务背景、自定义系统提示词、音频/SRT 文件、参考文档、钉钉 Webhook 及密钥。返回 Markdown 文本、结构化 JSON、任务编号。

4 完整业务处理流程

  1. 用户 Web 端录入：会议主题、业务背景，选择会议模板或填写自定义提示词
  2. 选择材料来源：上传音频 / 上传 SRT 字幕 / 上传参考文档 / 填写语雀文档链接
  3. 中台处理原始材料：音频 → ASR 转写；SRT → 解析；语雀链接 → 拉取 PRD 快照；本地文档 → 解析提取文本
  4. 中台组装完整 Prompt 上下文，调用大模型服务
  5. 得到 Markdown + JSON 双格式纪要结果
  6. 如果配置了钉钉 Webhook，则执行消息推送
  7. 全部元数据与结果写入数据库归档
  8. 用户可在页面预览结果，查看历史会议记录

6 质量与防幻觉设计

6.1 AI 幻觉约束策略

  1. 全部决策、变更、待办、风险，必须来自会议转写文本
  2. PRD 参考文档仅作为业务基线，文档有但会上未讨论的内容，严禁编造评审结论
  3. 会议口头讨论优先级高于 PRD 文档，发生冲突时以会议为准并标注变更
  4. 识别不到责任人、时间，统一标记【未指定责任人】【时间待确认】，禁止 AI 自行编造
  5. 过滤闲聊、跑题内容，只保留有效业务信息

6.2 上下文超限防护策略

超限程度处理策略
轻度超限（<10%）按比例均匀压缩会议转写文本（保留关键时间戳段落）
中度超限（10-50%）完整保留会议转写，截断 PRD 参考文档（保留首尾章节 + 关键标题）
严重超限（>50%）返回错误提示，建议用户缩短输入内容

不同大模型上下文窗口不同（DeepSeek 128K, GLM 128K, 通义千问 100K+），截断策略随模型配置动态调整。前端显示当前上下文占用情况。

7 部署方案

7.1 部署形态

单机轻量化部署，运行在内网机器，不需要 K8s、微服务集群。

  • 原型阶段：开发人员笔记本直接运行
  • 部门试用阶段：内网单机服务器部署
  • 后期平滑升级：SQLite 迁移 MySQL，增加异步任务队列，改造为正式中台

服务健康检查

  • 提供 /health 端点，返回服务状态（数据库连接、ASR 模型加载状态、磁盘空间）
  • 日志记录采用结构化格式（JSON），包含请求 ID、操作类型、耗时等关键字段

文件存储目录结构

data/
  uploads/          ← 上传的原始文件
    audio/          ← 音频文件（处理后定期清理）
    docs/           ← 参考文档
  snapshots/        ← 快照文件
    yuque/          ← 语雀文档快照（含图片资源）
    local/          ← 本地文档快照
  outputs/          ← 生成结果
    markdown/
    json/
  temp/             ← 临时文件（定期清理）

7.2 软硬件环境要求

项目说明
软件环境Python 3.10+；Faster-Whisper 依赖 PyAV（自带 FFmpeg 库）
硬件（CPU 模式）推荐 INT8 量化（compute_type="int8"），建议使用 small 模型
硬件（N 卡 GPU）大幅提升 Faster-Whisper 转写速度，支持 FP16 推理
依赖项大模型 API Key；语雀只读 Token（可选）；Python 文档解析库
文件上传安全音频 ≤ 200MB，文档 ≤ 20MB；MIME + magic bytes 双重校验；随机文件名

8 实施周期与里程碑

  • M1
    基础能力搭建 项目初始化、ASR 模块集成（Faster-Whisper）、CLI 测试脚本、异步任务队列框架 📅 3-5 天
  • M2
    参考文档接入 本地文档上传解析（docx/pdf/txt/md，含 PDF 扫描件检测）、语雀文档拉取与快照、HTML→Markdown 转换 📅 3-5 天
  • M3
    AI 纪要生成 LLM 适配器抽象层、模板管理、上下文组装、大模型调用、Markdown + JSON 双格式输出 📅 3-5 天
  • M4
    输出与存储 钉钉推送适配、数据持久化、SQLite WAL 配置、历史查询 API、健康检查 📅 2-3 天
  • M5
    前端界面 Web 可视化界面（表单、上传、预览、历史列表） 📅 3-5 天
📊 工期估算

整体原型全部落地：14-23 工作日（约 3-5 周）

M1-M4 后端核心能力：11-18 天

若优先交付 API + CLI 模式（跳过 M5），核心能力可在 2-3 周内完成

9 风险点与应对措施

风险应对措施
大模型输出不稳定，JSON 格式异常二阶段输出策略；优先使用结构化输出参数；支持宽松解析 + LLM 自修复三级降级
ASR 识别存在错字保留 SRT 输入模式；Faster-Whisper 不足时可切换 Qwen3-ASR-Flash
语雀 Token 权限变更友好报错；支持本地文档降级；快照保存历史版本
长音频转写超时阻塞异步任务队列；音频超过 30 分钟强制异步
大模型 API 调用失败指数退避重试（最多 3 次）；timeout=120s；熔断机制
扫描件 PDF 无法提取文本上传时检测 PDF 类型，提示用户改用原始文档
文件上传安全风险限制文件大小；MIME + magic bytes 双重校验；随机文件名

10 后续演进规划

🚀 演进优先级建议

以下按优先级从高到低排序：

  • 构建会议决策 RAG 知识库，支持历史会议检索问答 P0
  • 评审结果回写语雀文档 P0
  • 对接企业会议开放平台，实现会议结束自动拉取转写 P1
  • 纪要待办自动生成钉钉待办任务 P2
  • 增加简单用户权限控制 P2
  • 增加 PaddleOCR 或 Tesseract 支持扫描件 PDF 文本提取 P2
  • 支持 WebSocket 实时推送任务进度 P2

11 方案总结

本方案构建轻量化 AI 会议纪要中台，解决评审会议纪要痛点。

核心差异化能力：语雀 PRD 基线对照评审，弥补普通纪要工具只有录音文本、缺少需求上下文的短板。

架构优势：

  • 模型无关，可灵活切换大模型
  • 不依赖会议厂商企业版权限，前期原型落地成本低
  • 中台化架构预留扩展，未来可以演进为企业级正式服务
  • 数据内网闭环，保障业务信息安全
